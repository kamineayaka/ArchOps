# 探测任务是控制面上的数据；唯一的正常是策展值；控制面判决交回结果

一条合并键上的实际，要由探测交回结构化结果，才写得成观测值。云涛 欧已钉死：不另存异常、错误或未定义种类的目录；已在跑的 Host Agent 用心跳拉取任务（选项 A）；每一次交回由控制面判决。Agent 不判决。不是每个结果都进 AI。

## 决议

1. **探测任务**是控制面上的数据：哪台主机、间隔、命令，以及该命令的结构化结果如何成为一条合并键（对象 + 关系类型）上的观测值。
2. 唯一配置的「正常」是该合并键上的策展值。不存放异常、错误或未定义种类的目录。该目录被拒绝：长尾会继续要求新种类。
3. 已在跑的 Host Agent 在心跳上拉取自己的任务列表。任务的改动由下一次心跳带上。不因此重新打包或替换该 Agent。控制面不推送任务，也不 SSH 到该主机（ADR-0044）。这是选项 A，已钉死。
4. 一台主机至多一个执行探测任务的 Host Agent。有的主机没有。没有 Agent 时，本应由该 Agent 写出的策展事实停留在无观测，即观测空洞，不是冲突。
5. 一个 Agent 可以跑多条探测任务。任务彼此独立：各自的间隔、命令与合并键。一条任务读不出或逾期，只使那条关系变为观测空洞。该 Agent 在自己该回报的时间内什么都没交回，则该 Agent 已停，它的观测变为观测空洞。
6. 控制面判决每一次交回的结果。Agent 不判决。不是每个结果都进 AI。只有三种结局：
   - **可读且等于策展**：停。无冲突。不进 AI。
   - **可读且不等于策展**：冲突。可以附上证据。以后可以写一条 AI 建议；建议不是新状态，也不能定稿策展（与 ADR-0047 一致；本 ADR 不改写 ADR-0047）。
   - **读不出，或到期没有交回**：观测空洞，不是冲突。读不出包括命令错误、没有结构化值。允许的动作仍是恢复观测通道。

## 考虑过而拒绝的

- 存放异常、错误或未定义种类的目录，用来标出「不正常」：那仍是一套要覆盖完的分类，长尾会继续要求新种类。唯一配置的正常是策展值。
- 控制面推送任务，或 SSH 到主机下发任务、重新打包或替换已在跑的 Agent：Host Agent 直连控制面，控制面不 SSH 到主机（ADR-0044）。选项 A 已钉死。
- 一台主机放多个执行探测任务的 Agent，或把没有 Agent 写成冲突：没有观测不是两侧都可用且不等。
- 一条任务读不出或逾期，就掏空该 Agent 的全部观测：任务独立，只掏空那条关系。Agent 在自己该回报的时间内什么都没交回，才是 Agent 已停。
- 由 Agent 判决齐不齐，或每个交回都进 AI：判决在控制面。等于策展则停，不进 AI。

## 明确不改

- 冲突只在两侧都有当前可用值且不等时成立。空洞 ≠ 冲突。
- 交回了结构化值才进入前两种结局。值为不存在的观测消失，以及 ADR-0035 里源主机核验写出的成功或失败，仍是可用观测值，可与策展构成冲突。命令错误或没有结构化值才是读不出。
- 身份失联仍是标志，不是冲突状态。未绑定留在冲突案件之外。
- 没有用户、处理人。人审不记录操作者。
- 不引入 Spring Cloud。不实现编排层。
- ADR-0043、ADR-0044、ADR-0045 的栈、进程切分与代发运输不改。控制面不持模型密钥，不向主机 SSH。
- ADR-0047 不改写。AI 建议不是新状态，不能定稿策展。
- 心跳附带状态快照仍可写入观测（ADR-0031）。本 ADR 不把快照改成异常目录。
