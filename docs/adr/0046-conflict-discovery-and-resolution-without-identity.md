# 冲突主线只有发现与解决；人审是显式动作，不记录操作者

领域里没有用户、协作身份上的角色（高级角色 / 一般角色）、归属、已知悉、自任、指派、接受或处理人。ArchOps 冲突主线只剩两段：发现，以及解决。人审动作仍在，但是匿名的（选项 A）：系统只承认动作被显式请求，不记录是谁做的，也不按身份决定谁可以做。某部署若仍有登录或账号，那在领域之外，不得存成冲突、操作计划、改策展草案、诊断选支或确认关闭上的操作者、处理人、归属或角色。

## 决议

1. **发现**不变。摄入观测，与策展比对。冲突只在两侧都有当前可用值，且在合并键（对象 + 关系类型）上不等时成立。此定义不改。发现自动发生，不经人审。
2. **解决**是显式的人的动作：使两轨再次相等，然后确认关闭。未相等不得关闭。
3. **人审动作保留，且匿名**（选项 A），仅此四类：诊断选支；批准并冻结操作计划；改策展草案逐条确认；两侧相等后的确认关闭。「人审」的意思是该动作被显式请求，不是存在一行用户。
4. 系统不记录操作者，也不按身份授权。看见警告与看不见警告，不是领域里的协作身份，也不是处理人。
5. **G2** 若写受众：受众是一切能看见该警告的人。没有处理人，也没有归属方。时钟仍自冲突警告首次发出起算；空洞挂起不暂停。
6. 图模型里 K8s 节点相对集群的职责分类仍叫「角色」（ADR-0005）。本 ADR 拿掉的是协作身份上的角色（高级角色 / 一般角色），不是那条节点职责。
7. 「属于」所说的成员归属是图上的成员关系，不是冲突归属。

## 不再有效的句子

下列句子被本 ADR 取代。旧 ADR 正文不在本变更里改写；读到它们时，以本 ADR 为准：

- ADR-0039 所称合同里的协作身份，以及 CONTEXT 中「归属 ≠ 处理人」「仅已接受处理人可开/审/执行计划与确认关闭」，以及把用户、高级角色或一般角色写成领域概念的句子。
- ADR-0022、ADR-0023、ADR-0024、ADR-0025 的已知悉、归属、处理人、指派、接受、拒绝、转让、自任。
- ADR-0026 里「仅处理人选支并审计划」这一身份门禁。先警告后诊断、诊断只读可见，仍然有效。
- ADR-0032 里「空洞走与冲突同一套已知悉 / 归属 / 处理人协作」。空洞挂起、恢复后续同一合并键、观测消失是可用观测值，仍然有效。
- ADR-0037 里「仅再提醒冲突处理人与冲突归属方」。G2 起算、按事实类型的阈值、空洞挂起时钟继续、G3 由偏差扩大驱动，仍然有效。
- CONTEXT「冲突」条里的「已知悉期间」不是另一套升级条件。冲突升级仍是同一合并键上实际值变化（见「冲突升级」）。去掉的只是这个身份限定。

ADR-0019 的「值相等且须人确认才关闭」以及策展对齐步骤仍然有效。关闭仍不是静音，也不是未确认的自动关闭；已知悉不再是一种领域状态。

## 明确不改

- 空洞 ≠ 冲突。纯空洞不变成冲突。
- 未绑定留在冲突案件之外。
- 身份失联仍是标志，不是冲突状态，也不是用户流程。
- Q1=B / Q2=B（把空洞、未绑定、身份失联折进冲突状态机）保持未决。本 ADR 不采纳，也不关闭这个未决项。
- 解决断点不在范围：ABSENT 分叉不能开计划；修实际的命令仍是占位；已完成的计划不写观测。
- 不因此开工编排层、B-live、工作台、未绑定 10 或执行引擎票 02。
- ADR-0043、ADR-0044、ADR-0045 不改。
- AI 仍不能独自定稿策展；逐条确认仍在。
- 操作计划仍只在显式批准后冻结；失败即作废；禁止改步重试。
- 发现仍自动，不经人审。

## 考虑过而拒绝的

- 把门禁放宽，但把用户、角色、归属、已知悉、处理人留在领域里：身份还会写回冲突、计划、草案、选支和关闭。
- 人审仍记到某一用户（操作者、处理人、归属或角色）：与「领域没有用户」相反。部署侧登录不是领域事实。
- 连上述四类人审动作一并取消：选支、批准冻结、逐条确认、确认关闭仍是权力边界，只是不再对应某个用户。

## 后果

以后的代码须按此语义。本 ADR 不提供迁移、工单拆分或补丁：

- 处理人门禁去掉。开计划、审计划、执行、选支、确认关闭不再询问「是不是已接受的处理人」。
- 操作者标识一类列不再是领域事实。冲突、操作计划、改策展草案、诊断选支、确认关闭上，不得把它们当成操作者、处理人、归属或角色。
- 登录或账号若仍存在，留在领域之外，不得写进冲突、操作计划、改策展草案、诊断选支或确认关闭。

CONTEXT 只替换本 ADR 取代的句子，并指向本 ADR。
