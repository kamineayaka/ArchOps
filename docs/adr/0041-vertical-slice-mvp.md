# 竖切 MVP：一条冲突闭环

在 ADR-0039 合同与 ADR-0040 全量推倒前提下，第一条可演示切片如下。目标是验证三件套最小闭环，不是功能大全。

## 用户故事

策展容器 X `运行于` Host-A（已打 `archops.object_id`）→ Host Agent 心跳附快照报实际在 Host-B → 冲突警告（不阻塞于诊断）→ AI/规则诊断（B-obs+B-live，never guess）→ 处理人已知悉并自任或接受 → 选「修实际回 A」分支（跳过草案）→ 生成操作计划 → 人审 → 经 SSH 执行 → 执行后刷新观测 → 值相等进入待确认关闭 → 处理人确认关闭。

## 必须交付

1. **图/双轨**：物理主机、Docker 容器、`运行于`；策展写入（人/表单即可，AI 起草可后做）；观测由 Agent 快照写入。
2. **Agent**：单主机 Agent；心跳 + 容器列表快照（含标签匹配）；超时 → 观测空洞（本切片可只做超时检测，挂起冲突可简化）。
3. **冲突**：合并键对象+关系；警告；已知悉+处理人（可先只支持「自任处理人」，指派可后做）。
4. **诊断**：警告后异步诊断；处理人选支；纯修现场出计划；人审后执行。
5. **执行**：图内主机 SSH 执行计划步骤；受阻即停、计划作废；禁止工作台轻确认续跑失败计划。
6. **关闭**：策展值==观测值 → 待确认关闭 → 处理人确认。

## 明确不做（本切片）

自我迭代、指标告警、V-vision、网络可达核验、改策展/草案分支、高危名单全表、多租户、K8s/数据库对象、完整 RBAC 高级指派、旧架构提案/RAG。

## 建议实现顺序

1. 技术栈已选定（ADR-0043）；初始化/维护 Gradle 空应用 + 新迁移。
2. 策展 API：主机、容器、`运行于`。
3. Agent 协议：心跳 + 快照上报 + 控制面写入观测。
4. 冲突检测与警告。
5. 处理人 + 选支 + 操作计划 + 人审执行（SSH）。
6. 诊断最小版（可先规则模板，再接 LLM）。
7. 待确认关闭。
8. 一条手工/脚本冒烟：A→B 冲突 → 迁回 A → 关闭。

## 验收口诀

没有心跳快照就不能假装有实际；没有人审就不能执行；计划失败不能改步重试；没对齐不能关单。
