# 冲突不分类原因；案件带证据与解决动作，不带原因种类

产品不分类冲突为何发生。长尾的集群情形只增加证据，不增加种类。云涛 欧已钉死此决议。发现仍只看齐不齐；人能做的写回只有两条轨道，或把观测重新变成可用。因此原因不是一套必须覆盖完的分类，选支也不从规则种类里挑。

## 决议

1. **发现**不变。冲突只在两侧都有当前可用值，且在合并键（对象 + 关系类型）上不等时成立。纯空洞不开冲突。发现自动发生，不经人审。
2. **解决动作**是封闭的一小集，且都是显式的人的动作：修实际；改理想（草案逐条确认）；恢复观测通道。修实际与改理想用来使该合并键上两轨再次相等。恢复观测通道用来使观测重新可用。新的故障形态不增加动作，因为产品只能写两条轨道，或恢复观测。
3. **案件状态机**仍只量齐不齐，不量原因：开放；空洞期间挂起；两侧相等则待确认关闭；只有显式确认关闭才关闭。未相等不得关闭。
4. 案件携带证据与所选解决动作。证据包括心跳、快照、命令输出，以及两侧轨道值。案件不携带原因种类。
5. 诊断不再是一套有限的原因分类。今日规则引擎上的分叉——修实际回策展宿主、改理想、恢复观测通道、身份失联说明、ABSENT 核验——以及任何将来的「无法归类」，都不再是领域种类。不要用更大的枚举换掉它们。
6. **人审**仍是该动作被显式请求，不记录操作者，也不按身份授权（ADR-0046）。ADR-0046 所称「诊断选支」不再表示从规则种类里挑一个原因，而表示请求上列解决动作之一。批准并冻结、草案逐条确认、确认关闭仍是显式人审。
7. **AI 编排层**以后可以凭这些证据附一条建议。建议不是新状态，不能定稿策展，也不能跳过显式的人的动作。本 ADR 不建造编排层。

## 不再有效的句子

下列句子被本 ADR 取代。旧 ADR 正文不在本变更里改写；读到它们时，以本 ADR 为准：

- CONTEXT「AI 诊断」里：必须异步生成作为原因分类的诊断结果；分叉建议必须覆盖情形；选支必须基于当前未过时的诊断；升级后必须基于新诊断重走；不提供分支就不许给出指令。警告不因分类原因而阻塞、改策展须草案人审、纯修现场跳过草案、计划失败作废且禁止改写未终止计划、升级时旧选支与活跃计划作废、不披露策展不得给唯一落点，仍然有效。
- CONTEXT「分叉计划」里：分叉是各绑定假设的处理路径，选支必须从中挑。显式请求解决动作、不记录操作者，仍然有效。
- CONTEXT「观测空洞」里：把恢复观测通道写成诊断分叉种类，并在恢复后触发重诊。空洞期间允许的动作是恢复观测通道、禁止用过期实际给唯一落点、挂起不关闭、恢复后再按同一合并键继续或升级、旧选支与活跃计划作废，仍然有效。
- CONTEXT「禁止猜测」「扩图诊断」里：以编造分叉或「无法判断原因则诊断失败」把原因分类当成义务。资料不足不得假装确定、不得给唯一落点、扩图有轮次上限并列出仍缺的材料，仍然有效。
- CONTEXT「现场状态读取」里「以便判断原因」这一分类目的。读取不写观测或策展、不得读业务数据，仍然有效。
- ADR-0016 里「存在冲突时必须输出绑定假设的分叉计划」。受阻即停、不得改写未终止的已审定计划，仍以 ADR-0038 为准。
- ADR-0027 里「无当前诊断不可选支」「须按新诊断重选支」。升级时旧选支与活跃计划作废、不得继续执行指向过时实际的计划，仍然有效。
- ADR-0033 里「仅允许恢复心跳/通道/核验类分叉」这一分叉种类表述。禁止用过期实际给出现场唯一落点、挂起后旧计划作废、观测消失答「不存在」，仍然有效。
- ADR-0030 里「已满三轮仍无法判断（原因）则诊断失败」这一原因判决。子图默认一跳、两侧查找、最多三轮，仍然有效。
- ADR-0044 决议 7，以及 ADR-0041 出站 ADR 里「规则分叉兜底」作为原因分类、并因此才能选支。不得因无模型或无编排层挡住警告，以及挡住显式人审之后的执行，仍然有效。
- ADR-0044 决议 2 里编排层「交回分叉」作为原因种类。交回的若是建议，不是新状态。进程切分不改。

ADR-0038 的流水线仍然有效：改理想须草案逐条确认后再出操作计划；修实际跳过草案。ADR-0046 的发现、匿名与「不记录操作者」仍然有效。

## 明确不改

- 空洞 ≠ 冲突。纯空洞不变成冲突。空洞期间允许的动作是恢复观测通道，不是凭过期实际猜一个现场修法。
- 身份失联仍是标志，不是诊断种类，也不是冲突状态。不得把过期实际当成唯一落点。现场实体仍走未绑定，不静默升级。
- 未绑定留在冲突案件之外。
- 没有用户、处理人、已知悉、指派。人审是动作被显式请求。
- 不引入 Spring Cloud。不实现编排层。不做 ABSENT 执行、占位 SSH 或观测回写。
- ADR-0043、ADR-0044、ADR-0045 的栈与进程切分、代发运输不改。
- AI 仍不能独自定稿策展。操作计划仍只在显式批准后冻结；失败即作废；禁止改步重试。

## 考虑过而拒绝的

- 增加「无法归类」，用来收纳长尾：那仍是一种原因种类，长尾会继续要求新种类。
- 每出现一种故障就加一种规则分叉，或把今日分叉换成更大的枚举：产品写不了原因，只能写两条轨道或恢复观测。
- 保留规则种类当必选目录，只让编排层在种类里面写说明：选支就仍得来自原因分类。

## 后果

以后的代码须按此语义。本 ADR 不提供迁移、工单拆分或补丁，也不改规则引擎：

- 规则引擎停止充当原因目录。上列分叉不再是领域种类。
- 证据附在案件上。案件记下所选解决动作，不记原因种类。
- 解决动作仍是修实际、改理想（草案逐条确认）、恢复观测通道。
