# 产品只运维大数据平台；取消策展与观测的判断

平台要做的事是把存储和计算服务提供出去。不管租户作业对不对。云涛 欧已钉死：取消策展与观测的判断机制；第一版只做 HDFS 和 YARN。通用公民和「主机之间可达」会把范围拖长并漂移，不再作为产品主线。

## 决议

1. **产品只运维大数据平台本身。** 目的是对内对外提供该平台的存储与计算。不关注租户业务。稳定性与使用便利是范围；业务作业的对错不是范围。
2. **取消判断机制。** 不再用策展（理想）与观测（实际）对账，不再以「两侧都有可用值且不等」成立冲突，也不再以空洞、未绑定、身份失联组织主线。故障是平台当前不可用或不健康。告警就是当前故障。
3. **第一版对象只有 HDFS 和 YARN。** 映射只有三层：集群、服务角色、主机。HDFS 的角色是 NameNode 与 DataNode。YARN 的角色是 ResourceManager 与 NodeManager。一台主机可以承担多个角色。不再增加通用关系公民。
4. **资源配置**是人写下的平台配置：角色落在哪台主机，HDFS 的副本数与容量，YARN 队列的内存与 vcore。这是配置，不是理想与实际的对账。
5. **故障发现**由 Host Agent 在主机上采集：角色进程是否在，容量是否耗尽，节点是否丢失。控制面记录当前故障。Agent 不给故障分类。没有原因目录，也没有「无法归类」。
6. **告警**等于当前故障仍在。故障消失，告警结束。不用确认关闭，也不记录操作者。
7. **智能自愈**是一份已冻结的步骤，对应一条告警（例如拉起 DataNode，刷新 YARN 队列）。控制面仍一次只代发一步（ADR-0044、ADR-0045）。执行引擎仍做步骤断言。模型只能建议用哪份剧本，不能自己判步骤成功，也不能独自改配置。编排层进程仍未建造；第一版若做自愈，只用写死的几条剧本。本 ADR 不替换现有占位命令。
8. **后续只留边界，不在本 ADR 实现：** 对象存储；Spark on K8s、Flink on K8s 的计算资源。扩展时仍只运维平台本身，仍用集群、服务角色、主机这三层，不回到通用公民。

## 不再有效的句子

下列句子被本 ADR 取代。旧 ADR 正文不在本变更里改写；读到它们时，以本 ADR 为准：

- CONTEXT 开篇把产品写成「运维关系真相系统」，并把主生命线写成关系真相加策展/观测。产品主线改为大数据平台的资源配置、故障发现、告警、智能自愈。
- ADR-0001、ADR-0002、ADR-0009 把关系真相和双轨判断当作产品脊柱。判断机制取消。已落地的冲突与探测代码留到新模型能表达 HDFS/YARN 故障之后再删，期间不得再加票。
- ADR-0004 的「一张统一图、多种对象」。第一版对象只有 HDFS 与 YARN 的集群、角色、主机。
- ADR-0034 把主机之间可达当作运维范围。主机之间可达不再扩展。

## 明确不改

- 技术栈仍是 ADR-0043。公开 API 仍是 REST `/api/...`。Flyway 只增不改。
- 控制面、执行引擎、编排层的进程切分与单步代发仍是 ADR-0044、ADR-0045。自愈不得把一整份剧本交给执行引擎跑完，也不得让编排层直连主机。
- 三进程 Kubernetes 交付仍是 ADR-0049。本 ADR 不写清单，不建造编排层。
- Host Agent 仍留在主机上。控制面不 SSH 去采角色状态。
- 人审不记录操作者（ADR-0046）。没有处理人、已知悉、指派。
- 不引入原因种类（ADR-0047 的这一条仍然有效）。故障只带采集到的原始证据。
- 现有冲突、草案、探测判决接口停在原地。本 ADR 不删除它们，也不为它们再开票。

## 考虑过而拒绝的

- 保留策展/观测判断，只把对象收成 HDFS 与 YARN：判断机制本身被取消。配置是人写下的，故障是当前状态，告警不是两轨偏差。
- 第一版就覆盖所有集群类型，或同时做对象存储、Spark on K8s、Flink on K8s：范围会漂移。这些只留边界。
- 继续加通用公民，或把主机之间可达当作主线：映射只有集群、服务角色、主机。
- 自愈由模型判成功，或由编排层直接改主机：步骤成功仍只看执行引擎的断言；模型只建议剧本。
- 本 ADR 里替换修实际占位命令，或立刻删掉冲突与探测代码：占位命令与删除都另做。删除要等新模型能表达 HDFS/YARN 故障。

## 后果

新工作只按本 ADR。第一张实现票只做集群、服务角色、主机的配置，以及 HDFS/YARN 角色是否在的故障与由此产生的告警。自愈沿用现有单步代发，不在那张票里换占位命令。对象存储与 K8s 上的计算资源不在那张票里。
