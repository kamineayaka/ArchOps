# Spec: 探测任务判决的薄 UI

**Status**: 工单 01 **done**。  
**Basis**: [`docs/adr/0048-probe-task-control-plane-judges.md`](../adr/0048-probe-task-control-plane-judges.md)。判决 HTTP 已在 [`docs/specs/probe-task-control-plane-judges.md`](probe-task-control-plane-judges.md) 票 01 变绿。本刀不重开那张票，不改 ADR 正文。  
**Testing seams (confirmed)**: 页面完成定义与冲突去掉协作身份票 07、未绑定票 07 相同：`cd frontend && npm run build`，再加上 Vite 上按人的路径点一遍。Playwright 不是完成定义，也不是 CI 门槛。判决 HTTP（相等 / 不等 / 读不出 / 逾期）不重测。探测冲突上的解决动作若还不能打开草案或待审计划，只在控制面 HTTP 上补那一个行为，仍不重测判决。

## Problem Statement

人还不能在页面上保存探测任务，也看不到控制面已经做出的判决。冲突上的修实际 / 改理想、空洞上的恢复观测通道，没有一块不记操作者、不选原因的薄页。

## Solution

1. 人在一台主机上保存探测任务：命令，以及该任务的策展结构化值。该值是唯一的正常。同一主机上的多条任务彼此独立，各看各的判决。
2. 页面只展示控制面判决：
   - 可读且等于策展值：正常。
   - 可读且不等于策展值：冲突，并展示交回的原始证据。
   - 读不出，或到期未交回：空洞。
3. 冲突上人可以请求修实际或改理想。改理想打开草案，不写入策展。修实际打开待审计划。
4. 空洞上唯一动作是恢复观测通道。不提供修实际或改理想。
5. 页面没有原因选择，也没有操作者。人审请求不发送用户身份（ADR-0046）。

## User Stories

1. 人保存一条还没有交回的探测任务，读回命令和策展值，判决是空洞。
2. 同一主机再保存一条任务，两条的判决互不影响。
3. 控制面判为正常时，页面显示正常，没有冲突动作。
4. 控制面判为冲突时，页面显示冲突和原始证据；请求修实际得到待审计划；请求改理想得到开放草案，策展值不变。
5. 控制面判为读不出或逾期时，页面显示空洞，唯一动作是恢复观测通道。

## Out of Scope

- Host Agent 执行命令、重新打包 Agent、控制面 SSH 下发
- Kubernetes、三个 Deployment、编排层进程、编排层↔控制面 gRPC（ADR-0049）
- AI 建议正文、原因种类、「无法归类」
- 认领、已知悉、自任、指派、接受、拒绝、转让、处理人、归属
- 重开 ADR-0048 票 01 的判决用例

## Further Notes

- **Issue tracker**: [`.scratch/probe-task-thin-ui/issues/`](../../.scratch/probe-task-thin-ui/issues/)
- 心跳交回与逾期扫描仍是已有 HTTP。本页不执行命令。人刷新后看到控制面已经写下的判决。
- 探测冲突的修实际沿用现有待审计划。本页不启动执行。
- 改理想对探测冲突打开的草案在确认前不是策展。本页不提供逐条接受，因此不会把观测值写成策展。
