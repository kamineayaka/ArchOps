# 竖切 MVP（K1 绿场）

依据：ADR-0039 领域合同冻结、ADR-0040 全量推倒。  
目标：用**一条端到端故事**证明三件套最小闭环，不实现自我迭代/指标大盘/V-vision/多租户/网络可达全矩阵。

## 故事（验收剧本）

1. 运维在策展中创建物理主机 A/B、Docker 容器 X（写入不可变标签 `archops.object_id`），策展事实：X `运行于` A。  
2. Host Agent 向控制面报送心跳 + 状态快照：匹配到 X，观测 `运行于` B。  
3. 系统发出**冲突警告**（不得等诊断完成）；随后异步诊断（可读策展/观测/冲突元数据 + 受控 B-live；不足则 never guess）。  
4. 高级角色或处理人：已知悉 → 指定/接受**冲突处理人**。  
5. 处理人选分支「修实际回 A」（纯修现场，**跳过草案**）→ AI/规则生成操作计划 → 处理人审查通过 → 执行（经控制面受控 SSH，禁止旁路直连）。  
6. 执行后触发探测/快照刷新；若策展 A 且观测 A → **待确认关闭** → 处理人确认关闭。  
7. 负面验收：计划执行中心跳超时 → 冲突挂起、旧计划作废；敏感读业务数据 → 拒绝；未打标容器 → 不承诺升级链。

## 范围

### Must（本竖切）

| 切片 | 内容 |
|---|---|
| 控制面骨架 | 认证与角色（至少：高级/一般或可映射的 ADMIN/OPERATOR）、API 约定、运维隔离区部署草图 |
| 策展写 | 对象+`运行于`；草案逐条确认（至少支持人工录入；AI 起草可后置） |
| 观测 | Agent 心跳+快照；身份匹配；冲突比对与警告；空洞/挂起最小集 |
| 协作 | 已知悉、归属、处理人接受、单活跃计划 |
| 诊断 | 警告后异步；分叉建议；处理人选支（可先规则引擎+LLM 可选） |
| 执行 | 操作计划人审、冻结执行、受阻即停作废；执行后刷新观测 |
| 关闭 | 值相等 → 待确认关闭 → 处理人确认 |
| 工作台最小 | 能对图内主机受控执行计划步骤即可；完整 xterm 可薄 |

### 明确不做（本竖切）

- 自我迭代、权限白名单自动、指标告警  
- 网络可达核验矩阵、K8s/数据库全对象（可只留模型位，不实现探测）  
- 改策展分支全流程（草案冲突路径留到下一刀；Spec 见 `docs/specs/change-curated-draft.md`）  
- 像素视觉、多租户、旧模块兼容层  

## 建议交付顺序

1. **合同数据模型**：策展/观测事实、冲突、归属/处理人、计划（PG + 图存储选型落地）  
2. **Agent 协议**：心跳+快照、对象标签匹配、控制面入库  
3. **冲突引擎**：警告、升级挂起、G2 时钟可后置默认  
4. **协作 API + 最小 UI**：冲突列表、已知悉、选支、审计划  
5. **操作计划 API**：创建/送审/批准/启动/逐步执行；升级与空洞作废活跃计划（SSH 可先 stub）  
6. **执行器**：按计划逐步真实 SSH（凭证加密存储从第一天做对）  
7. **诊断**：先规则分叉，再接 LLM（出站策略另 ADR）  
8. **端到端剧本自动化/手工验收清单**  

进度：交付骨架（脚手架）已按 ADR-0043 重建；竖切故事 1–8 尚未实现。接手见 `docs/dev-handoff.md`。

## 技术栈（ADR-0043，选型会已冻结）

- 控制面：Java 21 / Spring Boot 3 / Gradle / **MyBatis-Plus**；PostgreSQL；**Redis**（多副本）  
- 图：v1 落 PG；专用图库 Later（目标架构 D2）  
- Agent：Python + systemd  
- 前端：React + Ant Design（嵌入 `archops:latest`）  
- 交付：`archops:latest` + postgres + redis；拆服务 / 图库 / 反向代理 Later  


## 完成定义

上述验收剧本 1–7 可在演示环境走通；负面验收至少抽测心跳超时挂起与业务读拒绝。
