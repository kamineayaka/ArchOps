### Q1 修法精度

审计的判别式本就带这个边界。它推荐的是「比较 `observed_at` 与 `markedAt`」并写成「**晚于**失联的 PRESENT 才算健康」；任何序关系判据都必然有相等分支，而它把判据下到了这个粒度却没点名。这属于**审计该预见而未预见**，量级 nit。08 的取舍是合理的：实现取 `!observedAt.isBefore(markedAt)`（相等判为已再命中 → 拒绝绑定），失败方向偏保守——宁可让人留着候选，也不替人做一次没确认过的并入；票尾自己把「当前无可达路径」记了档。04 清标之后该判据退化为「有没有失联标」，相等窗口进一步消失。

### Q2 连带后果

审计**部分**考虑过。C-2 的「Why it matters」已经预见消费歧义（「X 命中后到底消费哪一条、另一条是否回到待并入，没有合同答案」），并明确说要**新增** Flyway 加唯一约束。它没走到下一步：加了这条约束之后，在命中或 `absentObjectIds` 落地之前**没有任何 HTTP 回退路径**，于是故事 37 与故事 50 从可选变必做。这一步是票 08 票尾 `/code-review` 发现的，不是审计。

缺的检查类别不是「跨票影响面」这么泛，而是具体的一类：**修复后的状态可达性**。审计的整套探针都在问「现在的状态说了真话吗」，没有一步问「照这条推荐修完之后，哪些状态变得进不去或出不来，谁负责重新打开」。票 04 Comments 第 4 条与 Cycle G / H 的存在，就是这项缺检查的账单。

### Q3 探针方法

**干净，没丢证据。** 探针删了，但报告附录留了代码草稿与失败文本，而真正付钱的两条（探针 1、2）被另一次会话在票 08 Cycle A / B 逐字复现，失败消息同文。换成「留成待补断言的 TEST-GAP 清单」不会更耐用：本仓没有跳过测试的约定，TDD overlay 要求红灯出现在**实现那张票**的循环里（`docs/agents/tdd.md`「Witnessed red」），提交一批注定红或被忽略的测试只会多一个要维护的东西。耐用的载体是票内循环记录，不是审计文件——这一点已被证实。

### Q4 prompt 是否制造发现

强制裁决是把双刃刀，三条里两条回本。**P11 完全值得**：它是全份审计下游影响最大的一条，而它本来就是票 03 自己 Cycle G 记下的张力——prompt 只是不许含糊过去。**P7 表面是噪音**（裁决 FALSE-ALARM），但被逼着写完的那段裁决恰好逼出了「缺陷不在加了 BIND，而在选谁」，这才是 C-2 / S-3。**P10 纯噪音**：结论正确、下游为零，还外溢出 ST-1。

本可不写的：ST-2（自述假警报，且那次编辑从未进 main）、S-5（低价值，且 04 顺手收窄了它）、以及严格说 S-1（正确推后，至今仍推后）。校准结论：「即使是 FALSE-ALARM 也必须单列」这条规则，对**实现方自己已经记档的张力**（P11 这类）值得保留，对**审计员自己生出的怀疑**（P10 这类）应当取消——后者是在给自己的推测发编号。

### Q5 净值

**净值为正**，但正的边际来自两条发现，不来自报告的覆盖面。

付钱的部分：C-4 把 ADR-0012 B1 的主场景在 HTTP 上救回来（在它之前，能绑的只剩「从未标签命中过」的对象，而票 03 全部绑定用例都是这一种——04 的夹具会把这个前提固化）；C-2 拦住一个策展对象成为两个现场实体的本体，且是复现过的红灯而不是理论；S-4 拆掉一条会把撒谎的问法焊进套件的断言。三条全落在「接受绑定 / 命中收尾」同一片写入点上，全部被另一次会话独立复现——这份报告是**可证伪的，而且活下来了**，这是判正的决定性理由。

### W3 合同冻结的账

买到的：竖切 13 + 改策展 6 + 未绑定 5 张票之间没有语义漂移，`CONTEXT.md` 期间只改过一行工单指针。账单在解冻那天到期，最容易被冲击的四处：

- **合并键**（最贵）。`CONTEXT.md`「冲突升级」把合并键定为「同一对象 + 同一关系类型」，而「网络可达」是**有向**边、A→B 与 B→A 分开维护、分开冲突。可达一解冻，合并键必须带方向（或把边本身当主体），而这把钥匙被冲突升级、待确认关闭、草案作废、计划作废、`by-merge-key` 全线复用——改动最深的一处。
- **对象身份规则**。K8s 集群以 `kube-system` namespace UID 为主键（外部权威），容器以策展 ID + 不可变标签为主键。今天整条未绑定管线是容器形状的：候选键 = (`sourceHostId`, `runtimeId`)，原因只有 `MISSING_LABEL` / `UNKNOWN_OBJECT_ID`，绑定记忆按策展对象唯一。有外部 UID 的对象类型根本不产生 `MISSING_LABEL`——这是要加**第二种形状**，不是把现有的放宽。
- **边表 / CTE 邻域**。`属于` 与图库两项解冻打的是同一处：`诊断子图` 默认「合并键所涉对象及其一跳邻居」、`扩图诊断` 封顶三轮。只有 `运行于` 时一跳邻域是树；加上 `属于` 与可达就成环，同一段 CTE 与同一个轮次上限的实际含义变了（不是语义改动，是诊断夹具的意思变了）。
- **冲突生命周期里的双写**。Y2「策展对齐步骤」一解冻，计划步骤成为第二个策展写入者，而改策展票 04 已把「接受即写策展并立刻比对 → 待确认关闭」钉成唯一路径，两者都会触发同一合并键的比对。本刀 Spec 自己写着「与改策展『接受即写入』双写张力未在本刀打开」——这是记过账的债，不是没看见。

另一个方向的代价也要记：冻结同时封掉了便宜的修法。C-1 本可用一条问法优先级 ADR 收口，那个提案合并后被撤回，于是这条语义现在住在票 09 的验收里而不在合同里。这是冻结的账目，不是抱怨。

### W4 流程的可持续性

**确实在防漂移的（有证据）**：① witnessed red + 单一 HTTP 接缝——审计里为真的每一条都被**另一次会话**复现成红灯，失败文本对得上（08 A/B/C，04 A/B/C/G/H）；② 负面回归（竖切未打标不点亮升级链、absent 压过失联声明）在此后五张票里守住了五态互斥；③ 票尾两轴 `/code-review`——08 那次抓到了审计漏掉的故事 37 / 50 义务，便宜且回本；④ 冻结的 `CONTEXT.md` 本身：`git log` 显示期间只动过指针行。

**已是沉积的**：① 9 份 `docs/implement-*-0N-prompt.md`（共 17 个 `docs/*prompt*`）复述票 + overlay 已有的内容，而约束的真身在票内 Comments，多一份副本就多一处会过时；② frontier 编号同时写在 `AGENTS.md`、`CLAUDE.md`、两个 `.cursor/rules/*.mdc`、`dev-handoff.md`、Spec Further Notes 至少六处，每张票要同步改六个地方——防漂移装置自己在制造漂移；③ 两棵 skill 树（`.cursor/skills/` + `.agents/skills/`）；④ 把全宽度跨票审计当常规步骤。

**「C-1 的 ADR 化提案被合并后撤回」这条证据怎么读**：它标出了合同仪式转为负收益的刻度——当一条语义**能被单一读模型里的一条 HTTP 断言钉住、且只有一个所有者模块**时，ADR 只增加一处需要同步的地方，不增加一份保证；ADR-0039 的用途本是阻止代码悄悄改语义，而这种规模上，测试红灯的声音比 ADR 大。刻度之上（跨模块、跨多票、或两条 ADR 互相打架）ADR 仍是最便宜的工具。

- **保留**：witnessed red + 单一 HTTP 验收接缝；票尾两轴 code-review；跨模块语义仍走冻结的 CONTEXT + ADR；负面回归测试当永久合同载体；票内循环记录（它才是耐用证据，审计文件不是）。
- **压缩**：每票一份 prompt → 一份模板 + 票本身；frontier 只写 `dev-handoff.md` 一处，其余改为指针；两棵 skill 树合一；审计范围收到「票内 code-review 已点名的那条张力」，不再走 P1–P15 宽度。
- **停**：强制裁决审计员自己生出的 FALSE-ALARM 探针；为单一读模型的优先序新开 ADR（用票 + 一条会红的断言）；在票内审查什么都没发现的刀上重跑全宽度合同审计。

### W5 最大单点风险

**动手能力已经先于约束它的规则落地：连接工作台的三档处置在 HTTP 上没有任何闸门，而受控 SSH 执行与计划执行已经完成。** 只挑这一个，理由四条：① 能力在树上了——`dev-handoff.md` 记「SSH 受控执行 已完成（票 08）」，与真机之间只剩 `archops.ssh.mode=fake` 一个开关；② 它要服从的规则是 `CONTEXT.md` 里 _Avoid_ 最密的一簇（`破坏性命令` P1/P2/P3 分级、`敏感读拒绝` 且拒绝桶优先于高危桶、`图结构变更` 强制导流到操作计划、`工作台轻确认` 不得续跑失败计划、`工作台处置三档` 不许有第四档），今天全部只有散文；③ 与其他候选不同，它的失败在物理世界不可逆（`docker rm`、`iptables -F`），不是返工成本；④ 本刀 Spec 的 Out of Scope 亲手推后了「高危名单全表」与「完整 xterm」，也就是说这块的缺口是**已知且在扩大**的。

次席（落选）：单一 HTTP 接缝的回归成本曲线。20 个验收类 / 141 tests、每类 `AFTER_CLASS` 刷库，成本确实在涨——但它以 CI 变慢的形式**可见且可谈**，不是静默危害。

### W6 何时该重开合同

不是现在。三条可观察的触发条件：

1. **一个合并键必须承载方向或第三个维度时。** 信号：某张票写不出验收，除非说「同一对象 + 关系类型 + **方向**」（第一张要 `网络可达` A→B 与 B→A 各自成冲突的票必然撞上）。此时该修订 ADR 而不是绕，因为升级 / 作废 / 关闭全线都读这把键。
2. **两个策展写入者必须共存时。** 信号：两条代码路径都在触发同一合并键的比对，或有票提议压掉其中一次比对（Y2「策展对齐步骤」遇上改策展「接受即写入并立刻比对」）。ADR-0006 与 Y2 必须先在文字上和解——本刀 Spec 已把这条张力记为「未打开」。
3. **五态的优先序开始因调用方而异时。** 信号：出现**第二个**与问法要求相反的消费者（票 05 的诊断分叉要失联优先，票 09 的问法要空洞优先）。一个消费者一种序是票的事；两个消费者互相打架就是合同的事，因为这五个态本身是合同词。注意这不是重提 C-1 的 ADR 化（该提案已撤回）——触发条件是那个**第二个冲突消费者真的出现**。
